# Development

- Use the pinned Nix shell: `nix develop`. Run `make check` after changes and
  `nix flake check` after toolchain, packaging or Nix changes.
- Run `make conformance-setup` once, then `make conformance` for parser, checker
  or evaluator changes. The submodule stays pinned; do not update it implicitly.
- A passing inherited harness is not proof of full CEL conformance. Preserve
  explicit semantic, safety and benchmark limitations in user-facing docs.
- Keep the core library independent of the protobuf runtime. Protobuf adapters
  and wire-format conversions live in `cel-core-proto`.
- Preserve the upstream MIT/Apache-2.0 notices and author credit.

# Version control and releases

- Prefer jj when available. Preserve unrelated changes.
- Use Conventional Commit titles: `feat`, `fix`, `doc`, `docs`, `test`, `ci`,
  `refactor`, `perf`, `chore`, `revert`, `style` or `security`. Use `!` or a
  `BREAKING CHANGE:` footer for breaking changes.
- Follow `docs/releasing.md`. `changelog.md` is generated by git-cliff;
  `changelog.prev.md` preserves upstream history and must not be regenerated.
- Pin external GitHub Actions to full commit SHAs, disable persisted checkout
  credentials, and expose release tokens only to the steps that need them.
- GitHub source releases have one publisher. Never publish this fork under
  upstream's crates.io package names without a separate ownership decision.
